# SDR-RTL Scanner v0.8.7

**Исследовательский инструмент** для автоматического сканирования радиодиапазонов (FM, OIRT, HF, VHF) с использованием RTL-SDR. 
Собирает данные RDS, метео- и космическую погоду, а также качество GPS-приёма для контекста исследовательской станции. 
Проект ориентирован на создание базы радиостанций (по умолчанию — Санкт-Петербург) и легко адаптируется под любой регион.

> **Это не коммерческий мониторинг.** Это инструмент для исследования эфира, где «Условия приёма» — это контекст замера, а не вердикт о причинах.

## 🆕 Что нового в v0.8.7

*   **Per-station PPM**: каждая станция калибруется индивидуально (защита от многолучёвки), а не по одной «самой сильной».
*   **`tolerance_mhz=0.1`** в `show_diff`: сглаживает «сползание» пиков (например, `103.9 ↔ 104.0`), не считая их новой/потерянной станцией.
*   **Склейка `PS/PS+`**: сбор всех вариантов `PS` (даже битых типа `M5OARLO`), выбор лучшего по консенсусу и склейка с частотой/телефоном в `PS_full` (например, `METRO [766-0207]`).
*   **Полный `RadioText`**: выбор самого длинного варианта из всех собранных.
*   **Качество GPS (4 состояния)**: `CLEAR` (норма), `INDOOR` (слабый сигнал), `ANOMALY` (нет сигнала), `NO_GPS_HARDWARE` (нет модуля).
*   **Блок «Условия приёма» в HTML**: светофор (✅/⚠️/🚨/⚪) с деталями (fix, спутники, SNR, `jam`), **без координат** для приватности.
*   **Автоопределение региона**: по GPS/IP с подтверждением (`--yes`, `--no-detect`).
*   **Фикс `snap`**: частоты округляются до шага сканирования (`snap_freq(freq, step_khz)`), а не до 100 кГц.
*   **`MAX_OVERLAP_MHZ=0.5`**: защита от абсурдного перекрытия в широких шагах (например, `CB-27MHz`).

## 🚀 Быстрый старт

### 1. Установка зависимостей

**Аппаратное обеспечение:** RTL-SDR приёмник (RTL2832U) или совместимый.

**Программное обеспечение (Linux):**

# Python-библиотеки
pip install numpy pandas pyrtlsdr

# Утилиты rtl-sdr (rtl_power, rtl_fm)
sudo apt update && sudo apt install librtlsdr-dev rtl-sdr

# RedSea (декодер RDS) — через snap или сборку
sudo snap install redsea
# или
# git clone https://github.com/Osso/redsea.git && cd redsea && mkdir build && cd build && cmake .. && make && sudo make install

#Проверь, что команды доступны:

rtl_fm -h
rtl_power -h
redsea -h

**Базовый скан FM-диапазона (87.5–108 МГц)**

python3 SDR_RTL_Scanner.py --start 88 --stop 108

#скан FM-диапазона (87.5–108 МГц) с шагом 50 кГц и dwell 60 с:

python3 SDR_RTL_Scanner.py --start 88 --stop 108 --step 50 --dwell 60 --yes

#Интерактивный выбор региона

python3 SDR_RTL_Scanner.py --region '?'


**Режимы работы (помимо fullscan):**

python3 SDR_RTL_Scanner.py --mode update   # пере-сканировать RDS из базы
python3 SDR_RTL_Scanner.py --mode edit     # ручное редактирование name_ru
python3 SDR_RTL_Scanner.py --mode merge    # слияние Update в Base

Результаты сохраняются в data/SDR_Update_{region}_{timestamp}.json,
HTML-отчёт — в reports/SDR_Report_{region}_{timestamp}.html.

**Основные флаги**

Флаг			Описание
--start, --stop		Границы сканирования (МГц). По умолчанию 87.5–108.0.
--step			Шаг rtl_power в кГц. Для FM рекомендуется --step 50 (100 кГц — грубо, даёт «сползание» на 100 кГц).
--dwell			Время на станцию для RDS (сек). Для слабых сигналов --dwell 60 (35 — мало).
--rds-gains		Список усилений для RDS через запятую (-1 = auto). По умолчанию -1,50,25,10,0.
--threshold		Порог сигнала (дБ). Если -35 слишком низко — auto-threshold включится автоматически.
--snap			Округление частот (кГц). По умолчанию 100.
--region		Регион в формате CC.city (например, RU.spb). '?' — интерактивный выбор.
--yes, -y		Авто-подтверждение региона (для CI/скриптов).
--no-detect		Отключить автоопределение региона (только из --region / observer.json).
--antenna		ID антенны из antennas.json (например, ant_001).
--artifact		Тип аномалии распространения (например, tropospheric_duct).
--interference		Тип помехи (например, power_line).
--no-context		Отключить сбор контекста (METAR, SWPC, GPS) для обратной совместимости.

**Полный список — python3 SDR_RTL_Scanner.py `--help`**

## 🛰️ Качество GPS и «Условия приёма»

Сканер считывает данные с локального `gpsd` (если он запущен) и формирует **общий контекст приёма** на момент сканирования. 
GPS — это **опция**. Если модуля нет, программа **не падает**, а просто помечает контекст как «GPS недоступен».

### 4 состояния GPS

В отчётах и JSON используется нейтральная классификация, без спекуляций о причинах(природные или технические):

| Состояние (`gq_status`) | Иконка в HTML | Что видит программа |
|---|---|---|
| **`CLEAR`** | ✅ норма | Есть фикс (`mode >= 2`). Координаты доступны (но в HTML не выводятся для приватности). |
| **`INDOOR`** | ⚠️ слабый сигнал | Фикса нет, но видимы спутники с сигналом (типично для помещения). |
| **`ANOMALY`** | 🚨 нет сигнала | Фикса нет, и **все** видимые спутники имеют `ss = 0` (нет сигнала ни у одного). |
| **`NO_GPS_HARDWARE`**| ⚪ GPS недоступен | Нет данных от `gpsd` (модуль не подключен, сервис выключен). |

### Блок «Условия приёма» в HTML-отчёте

В верхней части отчёта (рядом с METAR и космической погодой) выводится свёрнутый блок:

> **Условия приёма:** ⚠️ слабый сигнал
> ▶ Детали
> * Fix: no fix
> * Спутников: 10 (используется: 0)
> * Средний SNR: 3.1 dBHz
> * Индикатор помех: 41/255

*   **Координаты (lat/lon) в HTML не выводятся** — только общие метрики (для приватности).
*   В JSON-файле поле `observation_context.gps_quality.position` всегда содержит `null`.
*   **`jam`** — это числовое поле `gpsd` (0–255). Это «индикатор» с приёмника. Низкий `jam` (10–50) — это нормально.

### Конфигурация GPS

В `config/observer.json` можно указать параметры подключения:
```json
{
  "gps": {
    "host": "127.0.0.1",
    "port": 2947,
    "timeout": 5.0
  }
}
```

## 📻 Работа с RDS: PS, PS+ и RadioText

Декодирование RDS выполняется связкой `rtl_fm` + `RedSea`. При слабом сигнале или многолучёвке RDS-группы приходят с ошибками. 
Сканер использует **сбор вариантов** и **консенсус**, чтобы вытащить чистые данные даже из «битых» пакетов.

### 1. Склейка PS (Program Service)

`PS` — это 8-символьное название станции, которое передаётся циклически. При плохом сигнале `RedSea` может выдать битые варианты (например, `M5OARLO`, `M*CARLO`).
Сканер собирает **все** варианты `PS` и применяет:

*   **Кластеризацию по Хэммингу**: варианты с разницей ≤ 2 символов объединяются в кластер.
*   **Консенсус по позициям**: если в кластере есть `M5OARLO`, `M-CARLO`, `M*CARLO`, то на второй позиции побеждает `-` (встречается чаще), и получается `M-CARLO`.
*   **`PS_full`**: если станция передаёт в `PS+` частоту или телефон, они добавляются в квадратных скобках. 
    *   Пример: `METRO [766-02xx]` (название + телефон рекламного отдела).
    *   Пример: `VESTI FM [89.3]` (название + частота).

> **Важно:** такие символы, как `DOPO*HOE` (Дорожное радио) или `* ABTO *` (Авторадио), — это **легитимные** названия (транслит с заменой `Ж` на `*`). Они **не** отбрасываются как «битые».

### 2. Полный RadioText

`RadioText` передаётся 64-символьными блоками. Если сигнал прерывается, `RedSea` может выдать только часть текста (например, `RECLAMA`).
Сканер собирает **все** варианты `RadioText` за время `dwell` и выбирает **самый длинный** (например, `RECLAMA (812)244-30-xx`).

### 3. Настройка RDS

*   **`--dwell 60`**: если станция слабая (SNR < 4 дБ), 35 секунд (дефолт) может не хватить для сборки всех RDS-групп. 60 секунд дают больше шансов.
*   **`--rds-gains "-1,50,25,10,0"`**: перебор усилений. Для разных станций оптимальный `gain` может отличаться (одна лучше ловится на 50, другая — на 25 или auto).


## 🗺️ Настройка под регион

Система поддерживает работу в любом регионе. Всё, что нужно — создать соответствующие JSON-файлы.

### 1. Справочник станций (база названий)

Файл: `regions/{region}.json`
Формат простой: словарь, где ключ — частота в МГц, а значение — название станции.

Пример (`regions/RU.spb.json`):
```json
{
  "schema_version": 1,
  "region": "RU.spb",
  "city": "Saint Petersburg",
  "country": "RU",
  "description": "FM and OIRT stations",
  "stations": {
    "87.5": "Дорожное радио",
    "88.0": "Ретро FM",
    "88.4": "Авторадио",
    "100.5": "Европа Плюс",
    "102.0": "Rock FM"
  }
}
```

### 2. Справочник диапазонов (шаг, модуляция, порог)

Файл: regions/radio_bands_reference.json
Здесь описаны границы диапазонов и их параметры по умолчанию.

Пример (фрагмент):
```
{
  "bands": [
    {
      "freq_min": 87500,
      "freq_max": 108000,
      "name": "FM-broadcast",
      "modulation": "WFM",
      "threshold": -35.0,
      "step": 100000
    }
  ]
}
```
Примечание: частоты в этом файле указаны в кГц (87500 = 87.5 МГц).

### 3. Конфигурация наблюдателя (Observer)
Файл: config/observer.json
Здесь задаётся регион по умолчанию, привязка к METAR-станции и (опционально) GPS.
```
{
  "name": "my_observer",
  "region": "RU.spb",
  "location": {
    "city": "Saint Petersburg",
    "lat": 0.0,
    "lon": 0.0,
    "altitude_m": 0
  },
  "metar_station": "ULLI",
  "gps": {
    "host": "127.0.0.1",
    "port": 2947,
    "timeout": 5.0
  }
}
```

Приватность: координаты (lat, lon) хранятся локально и не выводятся в HTML-отчёт.
    Если они не нужны, оставьте 0.0. Для работы GPS-контекста достаточно,
    чтобы был запущен gpsd на 127.0.0.1:2947.

### 4. Параметры антенны

Файл: config/antennas.json
Содержит профили антенн. Сканер может автоматически подстраивать усиление (gain),
если для диапазона указан default_gain.
```
{
  "ant_001": {
    "model": "RTL-FM-Dipole-V1",
    "type": "dipole",
    "gain_dbi": 2.15,
    "frequency_range_mhz": [87.5, 108.0],
    "default_gain": 25
  }
}
```

Как добавить новый регион (например, Москву)

    Создайте файл regions/RU.msk.json по образцу RU.spb.json.

    Если хотите, чтобы он использовался по умолчанию, измените "region": "RU.msk" в config/observer.json.

    Запустите сканер: python3 SDR_RTL_Scanner.py --region RU.msk --start 88 --stop 108 --yes.


## 🔒 Приватность и координаты

Проект создан как **исследовательский инструмент для личного использования**. Мы понимаем, что точные координаты места приёма могут быть конфиденциальной информацией. 

Поэтому в сканере реализован принцип **«координаты — только локально»**:

1.  **В HTML-отчётах нет координат.**
    В отчёте отображается только регион (например, `RU.SPB`) и блок «Условия приёма» (состояние GPS, количество спутников, `jam`), но **никогда** не выводятся широта и долгота.
2.  **В JSON-файлах координаты обнулены.**
    При сохранении результатов сканирования в `data/SDR_Update_*.json` поле `observation_context.gps_quality.position` всегда принудительно устанавливается в `null`. Это защищает от случайной утечки, если вы поделитесь JSON-файлом.
3.  **Локальное хранение.**
    Если вы сохраняете координаты для дальнейшего использования (например, для автоподстановки региона), они хранятся только в `config/observer.json` на вашем устройстве.

### Рекомендации для пользователей Git

Файл `config/observer.json` может содержать ваши личные данные (координаты, привязку к METAR-станции). 
Если вы планируете публиковать свой репозиторий, **настоятельно рекомендуется** добавить этот файл в `.gitignore`:

```text
# .gitignore
config/observer.json
```

Примечание: в репозитории уже есть пример конфигурации (если он есть), но лучше перестраховаться.

## 🔬 Статус: Исследовательский проект

Этот сканер задуман и разработан как **исследовательский инструмент** для энтузиастов, изучающих радиоэфир. 

**Что это значит:**
*   **Контекст, а не вердикт.** Блок «Условия приёма» и метрики GPS (включая `jam`) — это лишь **числовые факты** (сколько спутников видно, какой DOP, какой уровень индикатора помех). Программа **не делает выводов** о причинах этих явлений (погода, здания, помехи или что-то ещё). Интерпретация не входит в задачи исследователя.
*   **Физические ограничения.** Дешёвые RTL-SDR имеют свои пределы: 8-битный ADC (подвержен перегрузкам), ограниченная избирательность по соседнему каналу. Поэтому на результаты влияет буквально всё: качество антенны, положение в комнате, время суток.
*   **Только приём.** Скрипт не содержит функционала для генерации помех, управления передатчиками или несанкционированного доступа к сетям. Только пассивное сканирование и декодирование RDS.
*   **Без гарантий.** Программа предоставляется «как есть» (см. лицензию MIT). Авторы не несут ответственности за использование результатов в коммерческих или регуляторных целях.

⚠️ Ограничения и известные особенности

    Разрешение по частоте. Для FM-диапазона --step 100 (по умолчанию) может быть грубым: пик станции «плавает» на ±100 кГц. Используйте --step 50 для точного позиционирования.

    Слабый сигнал и RDS. При SNR < 4 дБ декодирование RDS невозможно физически. Увеличение --dwell (например, до 60 с) повышает шансы, но не гарантирует результат.

    Многолучёвка. В городских условиях сигнал приходит с разных направлений, вызывая интерференцию. Это влияет на качество RDS.

    Края диапазона. rtl_power имеет артефакты на краях сканируемого диапазона (DC-spike, спад АЧХ), поэтому крайние частоты могут определяться неточно.
